# nightly-steward

`export AOS_AGENT=agent:steward` before the first `kb` call. Attribution is the enforcement
substrate — the committer of every write is what the weekly grants audit checks — and this
pass runs while nobody is watching, so its edits must be attributable to it rather than to the
agent the user was last talking to. The tool never refuses on grants, so getting this wrong
produces a week of overnight changes indistinguishable from the user's own.

Run the `wt-steward` skill over the commitments base — one base, always private, named in
the registry as `commitments`. **One pass per night; never loop.**

Close out per the skill's own report section. `STEWARD: backlog clean.` is only the right
output when all five signals AND the backstop are empty; a night with nothing overdue but a
commitment stuck waiting still gets a report, never silence.
